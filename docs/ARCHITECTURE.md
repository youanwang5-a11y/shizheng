# 拾证技术架构

## 记录与界面

`MainActivity` 打开 Compose 页面。应用级 ViewModel 管理页面、录入和确认状态，`RecordRepository` 为界面提供本地数据。Room 版本 2 保留学期到记录、记录到证明的外键，新增类别表。记录以稳定的类别 ID 关联类别。内置类别 ID 沿用版本 1 的枚举字符串，自定义类别用 UUID。删除类别将其设为停用，保留既有记录的类别名与筛选可用性。同名类别重新添加时恢复原 ID。

日期沿用 ISO 文本列，空字符串表示无起始日期。无日期同时要求结束日期为空。学期日期列保留既有值，新学期的日期列留空。旧记录的学期关联原样保留，`manualTerm` 仅保留兼容字段。仓储初始化补齐学期预置表项，新增草稿从当前学期初始化，用户可改选。

保存、删除、备份和恢复由仓储互斥调度。录入中新增附件先落到应用私有目录，确认保存才纳入记录。数据库提交后回收不再引用的旧文件。进程重新启动时清理孤立附件及中断的恢复临时目录。

## 文件

系统照片选择器和 SAF 打开文件，系统相机写入一次性的 FileProvider URI。应用读取原件并复制到 `files/evidence/`，用随机 ID 命名，元数据包括显示名、类型、顺序、大小和 SHA-256。列表只在有对应照片时显示真实缩略图。图片使用 ImageDecoder，PDF 使用 PdfRenderer，Word 使用限于该文件的只读 URI 交给兼容应用。三类预览均可通过系统文件选择器另存原始字节。

## 备份格式 2

ZIP 包含 UTF-8 `manifest.json` 和 `evidence/<UUID>` 两类条目。清单格式标识为 `app.shizheng.backup`，包含版本号、学期、类别（含停用项）、记录和附件元数据。备份为普通 ZIP，可读取，需妥善保存。新版可读取格式 1，按旧规则校验并补齐预置类别。格式 2 支持无日期和自定义类别，须在 0.2.0 或后续版本中恢复。

恢复限制压缩包、目录、条目、清单、单附件和总解压量。校验 ZIP 目录边界、文件路径、重复条目、清单 CRC、格式、清单关系、日期、枚举、附件类型、文件大小和 SHA-256。校验完后暂存原件；确认替换时以新文件 ID 迁入私有目录，再以 Room 事务替换所有关系。文件准备或事务失败清理新副本，旧记录和原件保留。恢复保留记录 ID、附件关联、显示名、顺序及原始字节，应用内附件 ID 会重发。AI 配置和 Key 属于独立的本地凭据，未写入备份。

## AI 和扩展

`AiClient` 使用 HTTPS POST 调用 OpenAI Chat Completions 兼容接口，禁用重定向并保留证书校验。内置模式固定直连官方 DeepSeek 服务和 `deepseek-flash`。连接测试发送固定短句。草稿请求包含确认后的文字、活跃类别名称、整理指令和可选的 JPEG 图片副本。照片长边最多 2000 像素，原件保存在本地附件中。文字和模型转录用于核验返回的名称、事实和完整日期。模型结果只填当前草稿的空白字段，用户核对后保存。

用户自定义 Key 使用 Android Keystore 的 AES-GCM 本机存储。内置 Key 由 Windows 本地私有构建输入注入分发 APK，只用于官方固定域名。源码包、备份、调试包及应用日志均不包含内置 Key。带内置凭据的 APK 仅供私下试用，APK 可被逆向提取凭据。 `RecordExporter` 继续预留批量导出接口。

## 迁移

提交 `app/schemas` 中每版导出的 Room 架构。1→2 显式迁移新增类别表并写入八个预置类别。记录的类别列仍为 TEXT，因此无需重写旧记录，学期和证明关系留在原表。改变 ZIP 格式时单独提升格式版本。缺少数据库迁移路径时应用会提示无法加载数据。 [Room 迁移文档](https://developer.android.com/training/data-storage/room/migrating-db-versions.html)
