# 拾证技术架构

## 记录与界面

`MainActivity` 打开 Compose 页面。应用级 ViewModel 管理页面、录入和确认状态，`RecordRepository` 为界面提供本地数据。数据库采用 Room 版本 1，关系为学期一对多记录、记录一对多证明。表保存枚举、ISO 日期及外键。归档状态根据附件数计算。只有一个学期完整包含经历日期时才自动归入，手动选择不受学期日期编辑影响。调整学期时事务内重新计算所有自动归入记录。

保存、删除、备份和恢复由仓储互斥调度。录入中新增附件先落到应用私有目录，确认保存才纳入记录。数据库提交后回收不再引用的旧文件。进程重新启动时清理孤立附件及中断的恢复临时目录。

## 文件

系统照片选择器和 SAF 打开文件，系统相机写入一次性的 FileProvider URI。应用读取原件并复制到 `files/evidence/`，用随机 ID 命名，元数据包括显示名、类型、顺序、大小和 SHA-256。列表只在有对应照片时显示真实缩略图。图片使用 ImageDecoder，PDF 使用 PdfRenderer，Word 使用限于该文件的只读 URI 交给兼容应用，另存通过系统文件选择器。

## 备份格式 1

ZIP 包含 UTF-8 `manifest.json` 和 `evidence/<UUID>` 两类条目。清单格式标识为 `app.shizheng.backup`，包含版本号、学期、记录和附件元数据。备份为普通 ZIP，可读取，需妥善保存。

恢复限制压缩包、目录、条目、清单、单附件和总解压量。校验 ZIP 目录边界、文件路径、重复条目、清单 CRC、格式、清单关系、日期、枚举、附件类型、文件大小和 SHA-256。校验完后暂存原件；确认替换时以新文件 ID 迁入私有目录，再以 Room 事务替换所有关系。文件准备或事务失败清理新副本，旧记录和原件保留。恢复保留记录 ID、附件关联、显示名、顺序及原始字节，应用内附件 ID 会重发。AI 配置和 Key 属于独立的本地凭据，未写入备份。

## AI 和扩展

AI 默认关闭。`AiClient` 使用 HTTPS POST 调用 OpenAI Chat Completions 兼容接口，不自动跟随重定向。连接测试发送固定短句。草稿请求发送确认页显示的整理指令和经历原文。响应只转换为本地录入草稿。日期必须在原文中有完整年月日，事实字段要求来自原文，类别允许根据上下文归类。用户确认才保存。Key 使用 Android Keystore 的 AES-GCM 本机保护，OkHttp 不安装请求日志拦截器。

`AttachmentTextAdapter` 预留材料识别接口。`RecordExporter` 预留导出接口，接收结构化快照、原件读取函数及输出流。当前 UI 只提供已实现的操作。

## 迁移

提交 `app/schemas` 中每版导出的 Room 架构。改变表结构时提升数据库版本、注册显式或自动迁移，补充旧库升级测试。应用保持现有数据库，缺少迁移路径时加载失败。改变 ZIP 格式时单独提升格式版本并实现旧包转换或给出明确的兼容性拒绝。记录变更涉及的字段、恢复方式和验证版本。 [Room 迁移文档](https://developer.android.com/training/data-storage/room/migrating-db-versions.html)
