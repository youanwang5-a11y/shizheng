# 拾证技术架构

## 记录与界面

`MainActivity` 打开 Compose 页面。应用级 ViewModel 管理页面、录入和确认状态，`RecordRepository` 为界面提供本地数据。Room 保留学期到记录、记录到证明的外键，记录以稳定的类别 ID 关联类别。旧预置类别沿用原字符串 ID，「学业学情」和自定义类别使用 UUID。删除类别将其设为停用，保留既有记录的类别名与筛选可用性。同名类别重新添加时恢复原 ID。

日期沿用 ISO 文本列，空字符串表示无起始日期。无日期同时要求结束日期为空。学期日期列保留既有值，新学期的日期列留空。旧记录的学期关联原样保留，`manualTerm` 仅保留兼容字段。仓储初始化补齐学期预置表项，新增草稿从当前学期初始化，用户可改选。

首次欢迎完成状态存储在本机 SharedPreferences。旧版已初始化数据库且无欢迎标记时视为已完成。学期仍通过 Room 保存。

记录筛选在 ViewModel 维护学期、类别和级别的集合，空集合表示不限。学年选项复用导出页的预置学期对应关系。列表以同组取并集、各组取交集的方式筛选本机快照，全选直接使用当前结果的记录 ID。

保存、删除、导出、备份和恢复由仓储互斥调度。录入中新增附件先落到应用私有目录，确认保存才纳入记录。单条和批量删除共用 Room 事务，先确认所选 ID 存在，再分批删除记录并由外键级联删除附件元数据。数据库提交后回收不再引用的旧文件。进程重新启动时清理孤立附件及中断的恢复临时目录。

证明管理复用补充表单，按入口返回。记录详情直接打开证明管理时，返回或确认放弃会退出草稿并回到详情。从编辑表单进入补充页时，返回继续编辑原草稿。

Compose 白色主题集中定义颜色、字重和圆角。记录卡标题使用系统中文无衬线半粗字形，元数据使用随 APK 分发的思源宋体 CN 常规字重。主题使用离线字体和插画资源。 [思源宋体 2.003R 与 SIL OFL 1.1 许可](https://github.com/adobe-fonts/source-han-serif/tree/2.003R)

普通记录列表将底部浮层高度用于滚动末尾留白，列表的可见区域延伸到底部。垂直拖动控制胶囊收起和展开，横向滚动工具栏或附件时仍可使用浮层。「我的」与多选模式继续由页面为底栏预留空间。

## 文件

系统照片选择器和 SAF 打开文件，系统相机写入一次性的 FileProvider URI。应用读取原件并复制到 `files/evidence/`，用随机 ID 命名，元数据包括显示名、类型、顺序、大小和 SHA-256。列表只在有对应照片时显示真实缩略图。图片使用 ImageDecoder，PDF 使用 PdfRenderer，Word 使用限于该文件的只读 URI 交给兼容应用。三类预览均可通过系统文件选择器另存原始字节。

## 备份格式 2

ZIP 包含 UTF-8 `manifest.json` 和 `evidence/<UUID>` 两类条目。清单格式标识为 `app.shizheng.backup`，包含版本号、学期、类别（含停用项）、记录和附件元数据。备份为普通 ZIP，可读取，需妥善保存。新版可读取格式 1，按旧规则校验并补齐预置类别。格式 2 支持无日期和自定义类别，须在 0.2.0 或后续版本中恢复。

恢复限制压缩包、目录、条目、清单、单附件和总解压量。校验 ZIP 目录边界、文件路径、重复条目、清单 CRC、格式、清单关系、日期、枚举、附件类型、文件大小和 SHA-256。校验完后暂存原件；确认替换时以新文件 ID 迁入私有目录，再以 Room 事务替换所有关系。文件准备或事务失败清理新副本，旧记录和原件保留。恢复保留记录 ID、附件关联、显示名、顺序及原始字节，应用内附件 ID 会重发。AI 配置和 Key 属于独立的本地凭据，未写入备份。

## 记录导出

两种入口均提交所选记录 ID 给仓储。ZIP 包含带 BOM 的 UTF-8 CSV 和依序编号的证明原件。清单写入类别、学期及可选字段，转义 CSV 文本并处理可能被表格软件解释为公式的单元格。附件经大小和 SHA-256 校验后保留原始字节。归档先在应用缓存完成，再写入系统选择器目标。导出 ZIP 没有完整备份清单，因此恢复校验会拒绝。

## AI 和扩展

`AiClient` 使用 HTTPS POST 调用 OpenAI Chat Completions 兼容接口，禁用重定向并保留证书校验。内置模式固定直连官方 DeepSeek 服务和 `deepseek-flash`。连接测试发送固定短句。草稿请求包含确认后的文字、活跃类别名称、整理指令和可选的 JPEG 图片副本。照片长边最多 2000 像素，原件保存在本地附件中。文字和模型转录用于核验返回的名称、事实和完整日期。模型结果只填当前草稿的空白字段，用户核对后保存。

用户自定义 Key 使用 Android Keystore 的 AES-GCM 本机存储。内置 Key 由 Windows 本地私有构建输入注入分发 APK，只用于官方固定域名。源码包、备份、调试包及应用日志均不包含内置 Key。带内置凭据的 APK 仅供私下试用，APK 可被逆向提取凭据。

## 迁移

提交 `app/schemas` 中每版导出的 Room 架构。1→2 显式迁移新增类别表并写入八个预置类别。记录的类别列仍为 TEXT，因此无需重写旧记录，学期和证明关系留在原表。改变 ZIP 格式时单独提升格式版本。缺少数据库迁移路径时应用会提示无法加载数据。 [Room 迁移文档](https://developer.android.com/training/data-storage/room/migrating-db-versions.html)

0.3.0 继续使用 Room 2。可恢复备份格式 1 和 2，仍按格式 2 创建完整备份。

0.3.1 的长按和组合筛选只影响界面及记录查询，沿用相同的 Room 架构、迁移路径、备份与导出格式。

0.3.2 的主题和返回路径沿用 Room 2、1→2 迁移、备份格式 2（可恢复格式 1 和 2）及既有记录导出格式。

0.3.3 的记录浮层和筛选反馈沿用 0.3.2 的 Room 架构、迁移以及备份和导出格式。

0.3.4 将 Room 提升到 3。2→3 只变更类别数据，表结构、记录 ID 和附件关系沿用原设计。「社会实践」在原 ID 上改名为「社会工作」，原先停用的项继续停用。若已有启用的同名自定义类别，保留自定义项，旧预置项停用并保留历史名称。已有同名「学业学情」时保留该项及其状态。预置「培训」停用，原 ID 和记录关联保留。

完整备份继续写入格式 2。恢复格式 2 时使用备份中的类别及启停状态。格式 1 以原有类别 ID 校验后补齐新版预置类别，历史记录引用「培训」时补入停用的旧类别。新的「学业学情」使用符合旧版检查规则的 UUID。
